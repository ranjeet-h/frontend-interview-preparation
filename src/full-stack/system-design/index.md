# System Design

The 100-question system design guide is organized so you can study foundations first, then drill by difficulty, then review strategy before mocks.

## Chapters

| Chapter | Questions | What it covers |
|---|---|---|
| [Foundations](concepts.md) | 15 concepts | Proxies, scaling, messaging, auth, CAP, indexing, hashing |
| [Easy problems](easy.md) | Q16–Q35 (20) | URL shortener, cache, auth, email, leaderboard, and similar |
| [Medium problems](medium.md) | Q36–Q70 (35) | Instagram, Uber, payments, search, collaboration at product scale |
| [Hard problems](hard.md) | Q71–Q95 (25) | Transactions, sharding, HFT, media, ML platform, multi-tenancy, blockchain |
| [Specialist areas](specialist.md) | Q96–Q100 (5) | Disaster recovery, financial consistency, ad tech, circuit breakers, observability |
| [Preparation strategy](preparation.md) | Study plan | 8–12 week plan, checklist, resources |

## How to navigate

- Start with **Foundations** — every later answer assumes this vocabulary.
- Use **Easy → Medium → Hard** in order unless you're refreshing one family (e.g. only messaging systems).
- For several classics (URL shortener, auth, notifications, file upload), a **deeper Type D page** also exists under [Backend System Design](../backend/system-design/index.md). The chapter banks here stay compact; the backend pages go full whiteboard depth.

## Diagrams

- Mermaid snapshots appear at chapter level where they help orientation.
- Foundation and problem pages use text architecture diagrams you can redraw on a whiteboard in under two minutes.
